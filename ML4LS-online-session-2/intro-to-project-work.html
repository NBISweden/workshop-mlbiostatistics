Other project ideas


  • Supervised learning
    • Predict an outcome from a set of input features
    • Evaluate how well the model generalizes to new data
    • Build an interactive app that allows users to enter or select new data and explore predictions
  • Examples
    • Predict disease status or treatment response
    • Predict a continuous outcome, such as BMI or a biomarker level
    • Compare predictions, feature importance, or model performance

Other project ideas


  • Unsupervised clustering
    • Identify groups or patterns in your data
    • Characterize and interpret the resulting clusters
    • Build an interactive app that allows collaborators to explore the clusters, samples, features, or metadata
  • Examples
    • Patient subgroups based on clinical or molecular profiles
    • Cell/sample clusters based on omics measurements
    • Project new data onto existing clusters, where applicable

Choose your stack


Python → scikit-learn → Streamlit

  • Data handling: pandas
  • Machine learning: scikit-learn
  • Interactive app: Streamlit


R → tidymodels / other modelling packages → Shiny

  • Data handling: tidyverse
  • Machine learning: tidymodels, glmnet, etc.
  • Interactive app: Shiny

These are recommended options, not requirements. If your team already uses another suitable framework, you are welcome to use it.

Project requirements


  • Work in teams on a life science ML project
  • Start from a clear biological or research question
  • Use a supervised or unsupervised learning approach
  • Clearly define the samples, features, and outcome or structure of interest
  • Use a dataset that is:
    • large and complex enough for a meaningful ML analysis
    • computationally manageable on a standard laptop
    • suitable for analysis steps that take minutes rather than hours
  • Evaluate and interpret the results appropriately
  • Create a simple interactive application for predictions or exploration of results


Project reproducibility


  1. Code & workflow — scripts/notebooks and the complete preprocessing and analysis pipeline
  2. Documentation — README.md explaining what the project does and how to run it
  3. Environment — record software and package versions
  4. Licence — define how the work may be reused
  5. Citation — e.g. CITATION.cff explaining how to cite the project
  6. Versioning — Git + tagged releases preserve specific versions
  7. Archiving — e.g. Zenodo creates a persistent archive and DOI

Final deliverables


Each team submits

  1. Link to the interactive application
    • e.g. Streamlit, Shiny, or another suitable framework
  2. Link to the GitHub repository
    • complete analysis code and workflow
    • README.md with instructions
    • software/package versions
    • licence and citation information
    • final tagged release / archived version
    • CONTRIBUTIONS.md with brief documentation of each team member’s contribution

Team work


Use this session to get your project started as a team.

  • Get to know each other
  • Make sure everyone has a shared understanding of the project goal
  • Discuss and make an initial agreement on:
    • research question / project goal
    • dataset
    • supervised or unsupervised approach
    • programming language / tools
    • how you will communicate and work together
    • initial division of tasks

Before you leave


Write down initial project plan

Research question / project goal:
What do you want to investigate, predict, or discover?

Dataset:
What data will you use? Where does it come from?

Samples:

Features:
What variables or measurements will be used?

Type of task:

Expected output:
What would you like the model or analysis to reveal or do?
